# Risk Register

Likelihood and impact: L (low), M (medium), H (high). Owner: C (client),
T (build team, the phase named). Review at every phase gate.

| ID | Risk | L | I | Mitigation | Owner |
|---|---|---|---|---|---|
| R1 | **Search engines cannot reach the site.** The old origin resets every TLS connection from outside Iran (observed 2026-10-11: 39 bytes back, then reset). If the new host blocks foreign inbound traffic the same way, Googlebot, which crawls from abroad, cannot fetch a single page and the site will not rank, whatever its quality. | H | H | Ask the host whether international inbound traffic is open. In phase 3, deploy a test page and fetch it from this cloud environment (outside Iran). Before launch, run the Search Console URL Inspection live test. If blocked: switch to a host with international access or put a CDN with foreign edge nodes in front (for example ArvanCloud). Do not launch while R1 is open. | C, T phase 3 and 10 |
| R2 | **Deploy path blocked.** GitHub's servers are abroad; pushing to an Iranian host over SSH may fail for the same reason as R1. | M | H | Pull-based deploy: cPanel Git pulls a prebuilt `deploy` branch from GitHub (the client already uses this flow). Requires outbound access from the host to github.com; fallback is a release zip uploaded through cPanel. | T phase 3 |
| R3 | **Shared hosting limits.** PHP version, missing extensions (`intl`, AVIF support in GD or Imagick), no Composer or Node, cron limits, memory limits. | M | M | `ops:probe` command in phase 3; CI builds `vendor/` and assets; WebP fallback when AVIF is missing; file and database drivers only. | T phase 3 |
| R4 | **Missing real assets.** No dentist data, real photos, vector logo or video files yet. Without them the site cannot look premium or meet E-E-A-T. | H | H | Shot list delivered now; layouts sized for real photo ratios; labeled placeholders and a gaps list; phase 4 can start with structure but phase 9 blocks launch on missing dentists and photos. | C |
| R5 | **Content cadence versus medical quality.** One article every 2-3 days without dentist review risks thin or wrong medical content, which Google demotes on health topics and which can harm patients. | M | H | Editorial checklist that blocks publishing without reviewer and sources; templates; cadence only as fast as review capacity allows. | C, T phase 6 |
| R6 | **Medical advertising rules.** Unprovable claims (the «اولین» slogan), before/after use, comparisons with other dentists in the VIP/CIP copy, price claims. | M | H | Copy guidelines ban superlatives and disparagement; tier copy describes materials and process, never other dentists; consent on every case; the client confirms the «اولین» claim or the slogan is softened. | C, T phase 6 |
| R7 | **Slow and filtered networks.** International bandwidth in Iran is limited; any third-party script, font or map can stall a page. | H | M | Self-host everything; zero third-party requests except optional analytics loaded after `load`; budgets enforced in CI. | T all phases |
| R8 | **Sanctions-related service limits.** Google Maps JS billing is impossible from Iran; reCAPTCHA can be unreachable; Search Console and GA4 may need a VPN for the client. | H | M | Static map plus deep links; honeypot and rate limits instead of reCAPTCHA; analytics optional with admin data as the source of truth. | T phase 3 and 5 |
| R9 | **Booking spam and emergency misuse.** | M | M | Honeypot, time trap, rate limits, duplicate merge, triage gate, admin outcome field, misuse KPI. | T phase 5 |
| R10 | **Personal data exposure.** Phone numbers are personal data. | L | H | Role-based admin, no phones in logs or analytics, anonymization after a set period, HTTPS everywhere, privacy page. | T phase 5 and 8 |
| R11 | **Loss of old URL equity.** Without the backup there is no 301 map. | M | M | Get the backup; the client exports indexed URLs from Search Console if the old property exists; redirects manager with import. | C, T phase 6 and 10 |
| R12 | **Brand name inconsistency.** Five name variants on the old site dilute brand search and local signals. | H | M | One canonical name: «کلینیک دندانپزشکی سفید»; same NAP on the site, GBP, Neshan, Balad and directories. | C, T phase 4 |
| R13 | **Motion ambition breaks performance.** | M | H | Budgets are gates; one moment at a time; revert anything that breaks a budget; phones get lighter variants. | T phase 7 |
| R14 | **Messenger filtering changes.** WhatsApp or Telegram access in Iran can change overnight. | M | L | Call and form are the primary paths; messenger links are secondary and easy to swap in settings. | T phase 5 |
| R15 | **Slow callbacks waste leads.** Requests are only as good as the time to first call. | M | H | Admin "callback due" view in phase 5; Telegram or SMS alerts once enabled; a callback promise in copy only after the client commits to it. | C, T phase 5 and 8 |
| R16 | **Single approver bottleneck.** The client approves every phase. | M | M | Short gate asks (max 5 questions), screenshots instead of meetings, decisions logged so nothing is asked twice. | T all phases |
